# TL-EDITORIAL-EXCELLENCE-001 — Pass A Audit and Implementation Plan

Date: 2026-09-08

Status: implementation authorized; live production certification not yet authorized

## Authority and current state

The institutional publication architecture remains certified and unchanged. The active deployed generation path is the serverless V3 Factory pipeline in `functions/src/pipeline.ts`. Factory V2 is additive, `SHADOW`-only, publication-disabled, and not certified beyond its current checkpoints; this program will not promote it or route public intake through it.

Timeline Quality V3 and Source Authority V2 live publication remain **NOT CERTIFIED**. The Cuban Missile Crisis and Apollo 13 failures remain immutable negative evidence. Autonomous discovery remains paused. Repository policy records that both previously authorized live certification requests were consumed; a new production request requires separate explicit founder authorization after repository gates pass.

## Evidenced general failure modes

1. The active planner determines scope, candidate inventory, significance, selection, redundancy, and omissions in one provider response. A schema-valid response can therefore be internally self-confirming rather than independently challenged.
2. The plan contract models temporal structure but not the subject class (conflict, technology, science, movement, and similar), explicit inclusion/exclusion rules, opening/terminal tests, or title/summary promise. Scope drift can remain semantically invisible until a date or reference gate happens to catch it.
3. The schema requires 6–20 selected events during plan parsing. This correctly rejects over-selection, but it also communicates a minimum-selection target to the provider before sufficiency is established and cannot distinguish a faithfully sparse topic from an under-researched topic.
4. Candidate significance uses seven isolated numeric scores. The deployed selector has no explicit comparative essential/major/supporting decision, boundary role, turning-point role, or source-readiness state. Source-rich minor events can compete with source-poor major events without an explicit fail-closed distinction.
5. Temporal balance is primarily era-presence plus a 65% concentration threshold. It does not independently challenge unexplained gaps, weak modern coverage, or phase compression as editorial defects across different temporal structures.
6. Redundancy review is provider-declared and title duplication is the only independent deterministic duplicate signal in the active V3 path. Paraphrased or different-granularity duplication can pass if the plan does not report it.
7. Omission review is provider-declared by the same response that selected the events. There is no independent whole-product assessment of missing turning points.
8. Structured composition is verified against selected titles and dates, but final title, description, narrative progression, and reader-level publication worthiness receive no independent complete-product review.
9. Editorial repair regenerates the complete plan. Existing code does not bind repairs to the original scope contract, so repair can silently change topic class, boundaries, eras, dimensions, granularity, or the title promise.
10. Source Authority is evaluated after composition. One targeted evidence pass is bounded and fail-closed, but selection does not explicitly distinguish essential insufficiently supported milestones from well-supported minor candidates before committing the public set.

## Bounded implementation plan

### Pass B1 — explicit editorial contract

Extend the active plan with an immutable-in-attempt editorial contract: subject class, title promise, inclusion/exclusion rules, opening and terminal criteria, required turning-point coverage, and an editorially derived event-count rationale. Keep temporal structure separate from subject class. Preserve compatibility for immutable pre-program artifacts through an explicit legacy upgrader; do not silently default new provider output.

Add candidate editorial roles (`BOUNDARY`, `TURNING_POINT`, `MAJOR_DEVELOPMENT`, `CONTEXTUAL_SUPPORT`) and selection classes (`ESSENTIAL`, `MAJOR`, `SUPPORTING`, `EXCLUDE`). Require selected candidates to state why they are necessary and rejected candidates why omission does not distort the story.

### Pass B2 — deterministic contract and repair enforcement

Validate scope-contract coherence, opening/terminal representation, required turning-point representation, candidate role/class consistency, selected-set sufficiency, dimension/era references, chronology, precision, and selection-to-composition identity. Bind all editorial repairs to the initial scope contract and reject scope mutation. Event count remains the smallest sufficient set; inability to represent the topic faithfully within 6–20 fails closed.

### Pass B3 — independent reader-level gate

Add one bounded, schema-constrained reader evaluation after composition and before Governance. It receives only the locked plan, final timeline, and allowed evidence metadata. It assesses scope fidelity, chronological intelligibility, milestone significance, narrative progression, material omissions, redundancy, temporal balance, title/summary fidelity, and publication worthiness. It cannot override deterministic Timeline Quality or Source Authority; any failed gate routes to exceptional review. Permit at most one reader-feedback editorial repair while preserving the locked scope, followed by a final independent evaluation.

Persist the reader artifact, policy/model provenance, exact input/output hashes, criteria, findings, and verdict; propagate its reference and passing verdict through Governance and independently verify it at institutional transition.

### Pass C — heterogeneous regression

Create non-public deterministic fixtures for closed episode, crisis/conflict, biography, institution, technology, long-duration, and ongoing subjects. Add adversarial cases for over/under-selection, early concentration, stale endpoint, precursor/legacy excess, paraphrased redundancy, missing turning points, coarse dates in precise boundaries, context-as-event, famous-but-peripheral material, source-rich minor versus unsupported essential milestones, repair scope drift, and event-count pressure.

### Pass D — repository certification

Run Functions and root tests, Editorial Intelligence, Timeline Quality, Source Authority, Governance compatibility, Historical Library, Published Memory, Projection Engine, Search, Public Platform, both typechecks, lint, both builds, dependency audits, and security thresholds. Do not weaken tests or policies.

### Pass E — production boundary

After all repository gates pass, inspect current production state and request explicit founder authorization for a bounded heterogeneous live set because repository records state that prior authorizations are consumed. Do not submit production requests, resume discovery, edit negative evidence, or change production state without that authorization.

## Acceptance rule

Repository-green is necessary but insufficient. `EDITORIAL EXCELLENCE: CERTIFIED` requires authorized genuine production candidates, reader-facing inspection, heterogeneous success, at least one difficult fail-closed case, immutable complete lineage, and all certification conditions from the controlling goal.
